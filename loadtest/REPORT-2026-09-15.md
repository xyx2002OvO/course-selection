# 选课系统压测报告

日期：2026-09-15  
对象：本机 Docker 固定 cgroup 配额下的选课复刻（Gateway → Web → Dubbo 受理 → Outbox/CDC → Kafka → Worker `confirm()`）  
身份：`X-Student-Id`

**总评：本机配额下，受理运行点 1000 QPS；去掉限流后受理能稳住 1400 QPS。CDC + `confirm=12` 时完整选课在 hold-500 贴住。**

Nacos 运行点：`submit-global: 1000`，`hotspot-per-course: 80`。课程 `211–230` 共 20 门。429 是限流命中，不是崩溃。

hold-500 在本机配额下落库贴住受理。hold-600 起 SUCCESS 被 60000 学生池卡住，不是 CDC 跟不上。

## 口径

| 说法 | 数字 |
| --- | --- |
| 运行点受理 | 限流开启后 hold-1000 **998.7 QPS**，202 成功率 99.87%，p95 60ms |
| 受理天花板 | 限流关闭后 hold-1400 **1388 QPS**，202 成功率 100% |
| 完整选课 | CDC hold-500 受理 500、落库 **497** |
| 超限 | 运行点 1200–1800 多出的请求是 429；2000 到达率会打出 5xx |

异步是削峰：HTTP 202 先返回，`confirm()` 后面落库。hold-500 时两者几乎同一数字。
